## 复用对象与待核查边界

优先复用 [FlyVis 官方仓库](https://github.com/TuragaLab/flyvis) 及 [2024 年论文](https://doi.org/10.1038/s41586-024-07939-3) 中的连接组约束连续值视觉模型。本次未验证最新安装版本、预训练权重下载、输入节点数、API 或 Isaac Lab 兼容性。

FlyVis 提供视觉回路，不等于完整视觉—嗅觉—运动策略。拟选版本的输入布局、节点身份、输出活动选择和时间动力学必须先核查；不自行以 1500 个节点或未经核实的 4°–5° 感受野替代它。

## 计划扩展链路

相机渲染 → 按所选模型布局做空间采样／亮度处理 → FlyVis 动态网络 → 明确的视觉节点活动 → 策略核心。

| 部位 | 后续修改 | 接口影响 |
|---|---|---|
| SceneCfg | 增加实际机载相机与外参 | 图像批次、时间戳、视场和更新率 |
| 观测函数（拟新增视觉模块） | 将图像映射到模型要求的空间输入 | 19 维代理输入不再是完整 Actor 观测 |
| 视觉模型适配（拟新增） | 外部依赖加载模型与指定输出节点 | 输出节点清单、维度、时间状态及 reset |
| 策略／checkpoint | 消费视觉活动，记录模型版本与权重来源 | 输入形状与状态变化需要新 checkpoint |
| 训练入口 | 配置渲染和依赖版本 | 不能照搬 4096 个无相机环境的资源预算 |

不是把低维目标向量塞入视觉节点就称为视觉训练。原代理 tracking_state 应在正式感觉任务中退出 Actor，保留项须逐项说明其实际可获得性。

## 与 FlyDrones 数据层的分工和衔接

D:\repository 当前未发现 FlyVis 仓库，不能在源码索引中伪造本地路径；现阶段只保留官方链接，后续核对具体版本。已存在的 FlyDrones.retina 使用 96×72 图像、每眼 6×8 网格、软件光流和按索引的 retinotopy，不能替代本页的真实视觉模型布局。

正式衔接：相机 → FlyVis 输入布局 → 明确的输出活动／类型／空间信息 → 项目侧显式映射 → MaleCNS 子图的指定入口。

需要在实现前明确“在哪一层切开”：从 FlyVis 选择哪些输出，与 MaleCNS 哪些入口匹配；不同时把一套外算光流注入 T4/T5 又宣称下游自己完成了同一段视觉计算。神经元群同名不代表逐细胞一一对应，未知对应不能按数组顺序补齐。

具体映射资产、输出群选择和失败条件见 [[04 后续升级/07 感觉运动节点映射与可训练读出]]；上游本地事实见 [[06 本地代码库与复用清单]]。仍保留可选依赖，不把 FlyDrones 的泊松编码塞进 FlyVis 输出链路。
